# 問7 組込みシステム開発の知識メモ

過去問の本文は載せない。用語・計算の型・読み方だけを書く。
出題テーマは `../../past-topics/07_embedded.md`。内容は一般知識が中心。「低い」「高い」などの評価の記述は、IPA講評の原文（PDF）と照合済み（2026-11-15）。

## 1. 組込みシステムの構成

| 部分 | 役割 |
|---|---|
| センサー | 温度、重さ、距離など、物理量を電気信号に変える |
| A/D変換器 | アナログ信号を、デジタル値に変える |
| マイコン（CPU） | 値を処理し、判断する |
| アクチュエータ | モーター、ヒーター、ブザーなどで、現実に働きかける |
| 通信部 | 無線LAN、Bluetoothなどで、外部とやり取りする |

- 流れ: センサー → A/D変換 → マイコン（処理・判断） → アクチュエータ
- 設問は、「どのタイミングで、何を読み、何を出すか」を、本文の表・図から読む。

## 2. RTOSとタスク（令6春、令5秋、令7春）

### 基本用語
| 用語 | 内容 |
|---|---|
| RTOS | 決められた時間内に、処理を終えることを保証する（リアルタイム）OS |
| タスク | OSが管理する、処理の単位 |
| 優先度 | 複数のタスクが実行可能なとき、どれを先に動かすか |
| プリエンプション | 優先度の高いタスクが、実行中の低いタスクを中断して動く |
| タスクの状態 | 実行中／実行可能（待ち行列）／待ち状態（イベントなどを待つ） |
| 割込み | 外部の事象（ボタン、タイマー、センサー）で、処理を中断して、割込み処理を行う |

### タスク優先度の設計（令6春で「やや低い」）
- 原則: 応答の期限（デッドライン）が厳しい処理、周期が短い処理を、高い優先度にする。
  - 例: センサーの読取り（周期が短い）＞ 表示更新
  - ユーザー操作への応答が遅れないようにするため、操作を受け付けるタスクは高くする
- 低い優先度のタスクが、いつまでも実行されない（飢餓）ことがないか、確認する。
- IPA講評（令6春 設問2(1)）: 優先度の設計理由を問われて、「タスクの処理が始まるまでの動作順序」や「処理が終わった後の動作仕様」を理由にする誤答が多かった。理由は、処理の期限・応答性など、優先度そのものの根拠で答える。

### タスク間の連携
| 手段 | 使いどころ |
|---|---|
| イベントフラグ | 「何かが起きた」ことの通知 |
| セマフォ／ミューテックス | 共有資源の排他制御（同時に使わせない） |
| メッセージキュー（メールボックス） | データを、順番に渡す |
| 共有変数 | 簡単だが、排他を忘れると、データが壊れる |

- 令5秋 2(2)（低い）: タスクへ通知する「パラメータ」。タスクが処理に必要な情報（対象のID、値、状態）を、通知とあわせて渡す。何を渡さないと処理できないかを、本文のタスクの処理から探す。
- 令7春 3(2)（低い）: 仕様から、各タスクが必要な情報を読み取る。タスクごとに、「入力は何」「出力は何」を表にして、本文に当てはめる。

## 3. 状態遷移（令5秋、令4春、平31春）

### 状態遷移図・表の読み方
| 要素 | 意味 |
|---|---|
| 状態 | 今どの段階にあるか（待機中、加熱中、完了など） |
| イベント（遷移条件） | 状態を変えるきっかけ（ボタン、タイマー満了、センサーの値） |
| アクション（処理） | 遷移のときや状態の間に行う処理 |

- 平31春 設問3(1)（低い）: 遷移条件ではなく処理内容を書く、監視タスク以外のタスクの状態遷移を書く、という誤答が多かった。矢印のラベルが「条件」なのか「処理」なのかを、図の凡例で確認する。
- 令4春 設問3(3)は正答率が高かったが、三つの処理を全部挙げていない、関係のない処理を挙げる、という誤答があった。各状態と、その状態を維持するための処理を理解する。
- 令5秋 設問1(1)（やや高い）: 遷移条件に「障害物を検知していない場合」「収穫開始の指示を受けた場合」と書く誤答があった。ロボットの位置による状態遷移を読む。
- 令元秋 問8: 状態遷移図では、「処理」と「状態」を混同しない。
- 各状態で、何が起きたら、次にどこへ行くか、全部の組合せを表にして、抜けがないか確かめる。
- 状態を維持する条件（その場に留まる条件）も、問われることがある。

## 4. 時間・周波数・カウンタの計算（令2秋、令5春、令6秋ほか）

**失点が最も多い分野。** 本文の条件の読み落としと、単位の取り違えが原因になる。

### 単位の変換
| 変換 | 式・目安 |
|---|---|
| 周波数と周期 | 周期(s) ＝ 1 ÷ 周波数(Hz)。1MHz → 1μs、1kHz → 1ms |
| 接頭語 | k=10³、M=10⁶、G=10⁹、m=10⁻³、μ=10⁻⁶、n=10⁻⁹ |
| 時間 | 1s＝1,000ms＝1,000,000μs |
| データ量 | 1バイト＝8ビット。通信速度(bps)は、ビット単位 |

### カウントと時間
- タイマーの設定値と時間: 時間 ＝ カウント値 ÷ クロック周波数（分周した場合は、分周後の周波数で割る）
- カウンタが1周して、元に戻る時間（オーバフロー）: （最大値＋1）÷ 周波数

### 電池の駆動時間（令5春、令6秋）
- 駆動時間(h) ＝ 電池容量(mAh) ÷ 平均消費電流(mA)
- 平均消費電流 ＝ （各状態の電流 × その状態の時間）の合計 ÷ 周期
  - 型: 1サイクル内で、動作時の電流と時間、待機時の電流と時間を、表にして、時間で重みづけする
- 注意: 設問が指定する状態だけを含める。本文の条件（例: 位置通知要求があったときだけ動作する）を読み落とすと、平均電流が変わる（令5春 3(1)）。

### 省電力とクロック（令6秋）
- 動作周波数を下げると、消費電力が小さくなる（電力はおおむね周波数に比例）。ただし、処理が遅くなる。
- 最適なクロック周波数: 「処理が期限内に終わる範囲で、最も低い周波数」。処理に必要なクロック数÷時間の上限、で下限を出す。
- スリープ（待機）状態: 処理が不要なときは、CPUを止める。再開のきっかけは、外部イベント（割込み、ボタン、通信の着信、タイマー）。CPU自身は止まっているので、CPUが自分でスリープを解除することはない（令6秋 1(2)で「低い」）。

### 桁の扱い（令7春）
- 「小数点以下第2位を四捨五入」などの指示は、そのまま守る。計算の途中で丸めず、最後に丸める。

## 5. データの扱い（バッファ・フィルタ・A/D変換）

### リングバッファ（令4春で「低い」）
- 固定長の領域を、輪のように使い、書込み位置と読出し位置の2つのポインタで管理する。
- 終端まで行ったら、先頭に戻る。古いデータを、新しいデータで上書きする場合がある。
- 状態の判定
  - 空: 書込み位置 ＝ 読出し位置
  - 満杯: 次に書く位置 ＝ 読出し位置（1つ空けておく方式が多い）
- 通信が途切れたときに、データを一時的にためておき、復旧後に送る用途に使う。

### バッファ長とブロック長（令3春）
- ブロック長: 1回の処理で扱うデータの量
- バッファ長: 確保しておくデータの領域の大きさ
- 取り違えると、時間の計算（1ブロックに何ms分のデータが入るか）が狂う。どちらの数値か、本文の用語で確認する。

### フィルタ（令元秋、令3春）
| フィルタ | 効果 |
|---|---|
| 移動平均 | 直近のN個の平均。ノイズを平らにする（変化が遅れる） |
| ローパス | 低い周波数だけ通し、高い周波数（細かい揺れ）を除く |
| ハイパス | 高い周波数だけ通す |
| メディアン | 直近の値の中央値。突発的な外れ値に強い |

- 式が出たら、「何個前の値を、どの重みで足しているか」を言葉に直す。

### センサーの不正値への対処（令4秋で「低い」）
- ノイズや一時的な異常で、あり得ない値が読めることがある。
- 対処の型
  - 値の範囲チェック: 物理的にあり得ない範囲の値は、捨てる
  - 複数回測定して、平均や中央値を使う
  - 前回の値と大きく違う値は、すぐに採用せず、連続して出るか確認する
  - センサーを複数持ち、値を比べる
- チャタリング（スイッチの接点の細かい振動）: 一定時間、安定してから確定する（デバウンス）。

### A/D変換
- 分解能 n ビット: 2ⁿ段階で表す。基準電圧÷2ⁿ が、1段階あたりの電圧（最小の変化）。
- 標本化（サンプリング）周期が、変化の速さに対して長すぎると、変化を見逃す。

### 負の値の補正（令元秋）
- カウンタが1周して、小さい値に戻ることがある。差を取ると、負の値になる。
- 補正: カウンタの最大値＋1（周期）を足して、本来の差にする。

## 6. その他の頻出の考え方

- ポーリングと割込み: 一定間隔で状態を調べる方式／イベントが起きたときだけ処理する方式。割込みは、待機中の消費電力を下げやすい。
- ウォッチドッグタイマー: 一定時間内に「生きている」合図がなければ、システムが暴走していると判断し、リセットする。
- 優先度逆転: 優先度の低いタスクが資源を持つ間、優先度の高いタスクが待たされる現象。
- 通信障害時: 状況を、ステータスコードや、タイムアウトで判定する。再送、バッファへの保存で、データの欠落を防ぐ（令4春 2、令7秋 1(2) データ欠落）。
- 複数台のカメラ（ステレオカメラ）: 2台の視差から、距離を求める。本文に2台とあれば、両方を使う処理を考える（令3秋で見落としが多い）。

## 7. 解き方メモ

1. 本文の表と図から、「センサーが何を・いつ読むか」「タスクごとの優先度」を最初に整理する
2. 計算問題は、単位を先にそろえる。接頭語（k、M、m、μ）を書き出す
3. 条件（桁、台数、状態、位置通知要求があった場合のみ、など）に線を引く
4. 状態遷移は、「条件」と「処理」を分けて、表に書く
5. 「なぜその設計か」を問われたら、期限を守る、省電力、データの欠落を防ぐ、のどの目的かを決める

## 8. 確認問題

- 先に自分で選んでから ▶を開く対象はこのファイルの内容だけ

**問1** 1MHzのクロックの周期はどれか。
ア 1ms　イ 1μs　ウ 1ns　エ 10μs

<details><summary>答えと解説</summary>
イ。周期(s)＝1÷周波数(Hz)＝1÷10⁶＝10⁻⁶秒＝1μs。接頭語は、k=10³、M=10⁶、m=10⁻³、μ=10⁻⁶、n=10⁻⁹。
</details>

**問2** 16ビットのカウンタが、1MHzのクロックで動いている。最大値から1周して元に戻るまでの時間は、約何msか。
ア 約65.5ms　イ 約6.55ms　ウ 約655ms　エ 約65.5μs

<details><summary>答えと解説</summary>
ア。（最大値＋1）÷周波数＝65,536÷10⁶秒＝約0.0655秒＝約65.5ms。「最大値＋1」を使うのがポイントで、最大値の65,535をそのまま使うと、わずかにずれる。
</details>

**問3** 電池容量が1,000mAh、平均消費電流が5mAのとき、駆動時間は何時間か。
ア 20時間　イ 200時間　ウ 500時間　エ 5,000時間

<details><summary>答えと解説</summary>
イ。駆動時間(h)＝電池容量(mAh)÷平均消費電流(mA)＝1,000÷5＝200時間。平均消費電流は、各状態の電流×その状態の時間の合計を、周期で割って求める。設問が指定する状態だけを含める。
</details>

**問4** スリープ（待機）状態のCPUを、再開させるきっかけとして適切なものはどれか。
ア CPU自身が、スリープを解除する　イ 割込みやボタン、通信の着信、タイマーなどの外部イベント　ウ 時間が経てば、自動で解除される　エ 解除する方法はない

<details><summary>答えと解説</summary>
イ。CPU自身は止まっているので、自分でスリープを解除することはできない。再開のきっかけは、外部イベント（割込み、ボタン、通信の着信、タイマー）。
</details>

**問5** リングバッファで、「バッファが空」であることを判定する条件はどれか。
ア 書込み位置＝読出し位置　イ 次に書く位置＝読出し位置　ウ 書込み位置が先頭にある　エ 読出し位置が先頭にある

<details><summary>答えと解説</summary>
ア。リングバッファは、書込み位置と読出し位置の2つのポインタで管理し、終端まで行ったら先頭に戻る。イは、満杯の判定（1つ空けておく方式が多い）。
</details>

**問6** RTOSで、タスクの優先度を高くする原則として、適切なものはどれか。
ア 応答の期限が厳しい処理や、周期が短い処理　イ 処理時間が長い処理　ウ 最後に実行する処理　エ 先に作ったタスク

<details><summary>答えと解説</summary>
ア。ユーザー操作への応答が遅れないよう、操作を受け付けるタスクも高くする。あわせて、低い優先度のタスクが、いつまでも実行されない（飢餓）ことがないかも確認する。
</details>
