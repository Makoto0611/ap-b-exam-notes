# データベース設計の基本（問6 設問1・設問2を得点源にする）

問6は、SQL（設問3）だけでなく、**E-R図・関係スキーマの読み取り**（設問1・2）も出る。ここは、型を覚えれば取れる。

## 1. E-R図の読み方
| 用語 | 意味 | 覚え方 |
| --- | --- | --- |
| 実体（エンティティ） | 管理する対象（顧客、商品、注文など） | 表になる |
| 属性 | 実体がもつ情報（氏名、単価など） | 列になる |
| 関連（リレーションシップ） | 実体どうしのつながり | 外部キーになる |
| 多重度 | 1対1、1対多、多対多 | 線の端の形で表す。**必ず凡例に従う** |
| 外部キーを持つ側 | 「多」の側 | 矢印は多の側へ向ける（凡例による） |
| 多対多 | そのままでは表にできない | **連関実体（関連表）**を間に入れ、複合主キーにする |
| 自己参照 | 同じ実体の中のつながり（部署の階層など） | 上位部署IDが部署IDを参照する |
| 代用キー | 意味のない連番を主キーにする | 複合主キーが長いときに使う |
| スーパータイプ／サブタイプ | 共通部分と個別部分に分ける | 共通の属性を上位へ |

### 令4秋・令7秋で×になった型（問6）
| 型 | 防ぎ方 |
| --- | --- |
| 凡例の表記を使わず、文字で書いた（「1対多」「多対多」） | 設問の「凡例に倣うこと」に線。矢印の向きで答える |
| 表の要件を、E-R図の属性・関連に結びつけていない | 要件の表を1行ずつ、属性・関連に対応づける（「年月ごと」→年月の属性） |
| 「端末は2年ごとに交換」のような本文の事情を、多重度に反映していない | 本文の事情から、1対多か1対1かを決める |
| 主キーの条件（UNIQUEを指定しない）を読み落とした | 表の前後のただし書きに線を引く |

## 2. 正規化
| 段階 | 何をするか | 判断の手がかり |
| --- | --- | --- |
| 第1正規形 | 繰返し項目をなくす（1つの欄に1つの値） | 1行に同じ種類の列が並ぶ（商品1、商品2…） |
| 第2正規形 | **主キーの一部だけ**で決まる列を、別の表へ分ける | 複合主キーの表で起きる |
| 第3正規形 | **主キー以外の列**で決まる列を、別の表へ分ける（推移的関数従属をなくす） | 「顧客ID → 顧客名」のような関係が主キー以外にある |

覚え方: 第2は「主キーの一部」、第3は「主キー以外」。

## 3. ビュー・インデックス
| 用語 | 中身 | 使いどころ |
| --- | --- | --- |
| ビュー（`CREATE VIEW`） | 検索結果に名前を付けた**仮想の表**。実データはもたない | 見せたくない列（暗証番号など）を隠して権限を与える |
| インデックス（`CREATE INDEX`） | 検索を速くするための索引 | 検索が多い列。**更新は遅くなる** |

令4秋 設問3 j の考え方: 暗証番号を、上長だけが参照できる → 列を指定した `GRANT SELECT (列, 列)`、または、列を隠したビューに権限を与える。

## 4. トランザクション・排他制御
| 用語 | 意味 |
| --- | --- |
| ACID | 原子性（全部成功か全部失敗）、一貫性、独立性（隔離性）、耐久性（確定後は失われない） |
| COMMIT／ROLLBACK | 確定／取消 |
| 共有ロック | 読取り用。ほかの読取りは許す |
| 専有ロック | 書込み用。ほかの読取り・書込みを待たせる |
| デッドロック | 互いにロックを待って止まる |
| 2相コミット | 複数のデータベースで、全部確定するか全部取り消すかをそろえる |

## 6. 確認問題

- 先に自分で選んでから `<details>` を開く。対象はこのファイルの内容だけ

**問1** E-R図で、多対多の関連を、そのままでは表にできない。どのようにするか。
ア 連関実体（関連表）を間に入れ、複合主キーにする　イ 外部キーを2つ増やす　ウ 属性を1つの欄にまとめる　エ ビューを作る

<details><summary>答えと解説</summary>
ア。連関実体を間に入れ、複合主キーにする。複合主キーが長いときは、意味のない連番を主キーにする代用キーも使う。
</details>

**問2** 第2正規形で行うことはどれか。
ア 繰返し項目をなくす　イ 主キーの一部だけで決まる列を、別の表へ分ける　ウ 主キー以外の列で決まる列を、別の表へ分ける　エ インデックスを付ける

<details><summary>答えと解説</summary>
イ。複合主キーの表で起きる。アは第1正規形、ウは第3正規形（推移的関数従属をなくす）。覚え方は、第2は「主キーの一部」、第3は「主キー以外」。
</details>

**問3** 凡例の表記で書くよう指定された設問で、関連を答えるとき、適切なものはどれか。
ア 「1対多」と文字で書く　イ 凡例の矢印の向きで答える　ウ 「多対多」と文字で書く　エ 空欄にする

<details><summary>答えと解説</summary>
イ。令4秋・令7秋で、文字で書いて×になった型。設問の「凡例に倣うこと」に線を引く。外部キーを持つ側が「多」で、矢印は多の側へ向ける（凡例による）。
</details>

**問4** ビュー（CREATE VIEW）の説明として適切なものはどれか。
ア 検索を速くするための索引　イ 検索結果に名前を付けた、実データをもたない仮想の表　ウ 複数のDBの確定をそろえる仕組み　エ 繰り返し項目をなくす設計

<details><summary>答えと解説</summary>
イ。見せたくない列（暗証番号など）を隠して、権限を与える使い方がある。アはインデックス、ウは2相コミット。
</details>

**問5** インデックスについて、適切な説明はどれか。
ア 検索も更新も速くなる　イ 検索は速くなるが、更新は遅くなる　ウ 更新だけが速くなる　エ 実データを持たない仮想の表

<details><summary>答えと解説</summary>
イ。検索が多い列に付ける。更新のたびに、インデックスも更新するので、更新は遅くなる。
</details>

**問6** トランザクションのACID特性のうち、「全部成功か、全部失敗か」を表すものはどれか。
ア 原子性　イ 一貫性　ウ 独立性　エ 耐久性

<details><summary>答えと解説</summary>
ア。一貫性、独立性（隔離性）、耐久性（確定後は失われない）と合わせてACID。COMMITで確定、ROLLBACKで取消。
</details>
