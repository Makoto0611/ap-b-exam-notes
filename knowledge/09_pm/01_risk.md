# プロジェクトマネジメント 01 リスクマネジメント

午後（科目B）の問9（プロジェクトマネジメント）で問われる知識のまとめ。
過去問の本文は載せず、「何が問われたか」と「その答えに必要な知識」だけを書く。

- 出典の書き方: 令4秋 問9 = 令和4年度秋期 問9
- IPAの採点講評は受験者全体の傾向であり、個人の評価ではない

---

## 1. ○BS の対比（混同注意）

| 略称 | 正式名称 | 分解する対象 | 例 |
|---|---|---|---|
| WBS | Work Breakdown Structure | 作業 | 設計 → 画面設計、DB設計 |
| RBS | Risk Breakdown Structure | リスク（要因別） | 技術 → 新技術の習熟不足 |
| OBS | Organization Breakdown Structure | 組織・体制 | PMO → チーム → 担当者 |
| CBS | Cost Breakdown Structure | コスト | 人件費、外注費、機材費 |

- 見分け方: 何を分解しているか、で決める。リスクの整理ならRBS。
- RBSは、リスクをカテゴリ（技術、外部、組織、プロジェクト管理など）に分け、その下に個々のリスクを並べる。目的はリスクの抜け漏れ防止。
- 出題: 令4秋 問9 設問1（「特定された全てのリスクを要因別に区分し、詳細化して体系的に整理する」ものを3字で）。講評で正答率が低いとされた。

---

## 2. リスクマネジメントの流れ

1. 計画（RBS、役割、判断基準の決定）
2. リスクの特定（洗い出し）
3. リスクの分析
   - 定性的分析: 発生確率×影響度で順位づけ（確率・影響度マトリクス）
   - 定量的分析: 金額や日数などの数値で評価（期待金額価値、デシジョンツリー、感度分析、モンテカルロ・シミュレーション）
4. リスク対応の計画
5. 実施・監視（新しいリスクの特定を継続する）

- リスクの特定は、1回で終わらない。プロジェクトの進捗に合わせて継続する。
- IPA講評（令5春 問9 設問3(1)、低い）: リスクの定性的分析・定量的分析は重要な作業なので、必要な手法を理解する。設問3(2)は「費用面の」対応策を求めたのに、他の対応策を答える誤答が多かった（平均的）。
- 出題: 令4秋 問9 設問4（進め方に追加する活動。答えは「進捗に従ってリスクの特定を継続して行う」）。

## 3. リスクの特定に使う手法

| 手法 | 内容 |
|---|---|
| ブレーンストーミング | 参加者が自由に意見を出す |
| デルファイ法 | 専門家に匿名で繰り返し意見を求め、収束させる |
| チェックリスト | 過去の事例から作った一覧で確認する |
| 特性要因図 | 原因の候補を魚の骨の形に整理する |
| SWOT分析 | 強み・弱み・機会・脅威で整理する |
| 前提条件分析 | 前提が崩れたときのリスクを見る |

- 特性要因図は、リスクと原因の候補の関係を系統的に図解して分類・整理する図。出題: 令4秋 問9 設問2(2)。
- IPA講評（PDFで確認）: 令4秋 問9 設問2(1)は「高い」。ブレーンストーミングや、過去のプロジェクトのリスク一覧でのチェックは有効だが、過去に経験のない技術を使うときは、有識者を参画させるなど、状況に応じた適用が必要、とされている。
- 方法の欠陥を問う設問（令4秋 問9 設問2(1)）の考え方（本人の解き直しの記録による）
  - 聞かれているのは「事実」ではなく「その方法では特定できない理由」。
  - 経験のない領域（今回はAI機能）のリスクは、社内メンバーや過去のプロジェクトの知見だけでは特定できない。知見のある外部（技術支援のT社）を入れていないことが欠陥。

## 4. リスクへの対応

### 脅威（悪い影響）

| 対応 | 意味 | 例 |
|---|---|---|
| 回避 | 原因をなくす。計画を変える | 不確実な技術を使わない |
| 転嫁 | 第三者に移す | 保険、外注の契約（固定価格） |
| 軽減 | 発生確率や影響を下げる | 事前検証、人員追加 |
| 受容 | 何もしない。予備を持って備える | 発生したら対応する |

### 好機（良い影響）

| 対応 | 意味 |
|---|---|
| 活用 | 確実に実現させる |
| 共有 | 実現しやすい第三者と組む |
| 強化 | 確率や影響を大きくする |
| 受容 | 起きたら利益を受け取る |

### 関連用語
- リスク登録簿: 特定したリスク、評価、対応、担当者を一覧にしたもの
- 残留リスク: 対応した後も残るリスク
- 二次リスク: 対応した結果、新たに生じるリスク
- トリガー（兆候）: リスクが起きそうなことを示すサイン
- コンティンジェンシー予備: 既知のリスクに備える予備（時間・コスト）
- マネジメント予備: 未知のリスクに備える予備

## 5. 定量評価: 期待金額価値（EMV）とデシジョンツリー

- 期待値 = 発生確率 × 影響額
- 複数の対応案がある場合
  1. 案ごとに「確実に払う金額 + 確率 × 追加分」を表にする
  2. 期待値が最小（コスト）または最大（利益）の案を選ぶ
- 令4秋 問9 設問3(2)の考え方（本文の数値は省略、構造だけ）
  - 何もしない案: 遅延1日あたりのコスト × 最大遅延日数
  - 対応案: 対応コスト + 確率 × 発生したときの追加コスト + 確率でない分の残りコスト
  - 案ごとに期待値を出し、最小を選ぶ
  - 設問が「最大値の期待値」と聞くときは、発生した場合の最大の追加コストに確率を掛ける
- 検算のコツ: 設問が1つの答えを聞いているのに、複数の案が同じ条件を満たしたら、計算を疑う。
- 講評: 令4秋 問9 設問3(2)（追加コストの最大値の期待値の計算）は、やや低かった。

---

## 6. 解き方メモ（この分野）

1. 設問が問う種類を決める: 用語／事実／方法の欠陥／計算
2. 略語は、何を分解・整理するかで見分ける（WBS=作業、RBS=リスク）
3. 「理由」の設問は、事実ではなく、その方法・計画の欠陥を書く
4. 計算は、案ごとに表を作ってから比べる。直感で番号を選ばない
