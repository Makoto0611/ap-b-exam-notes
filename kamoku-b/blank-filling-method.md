# 空欄の埋め方（B科目 問6 SQL）

知識があっても、「空欄に何を書くか」が分からないと解けない。そこで、本文から答えを組み立てる手順を決めておく。

## 4ステップ
1. **空欄の位置を見る:** 前後のSQLから、入るのが「型」「制約」「キーの種類」「権限」のどれかを決める
2. **本文で、その列・その表の条件の行を探す:** 空欄の記号（a、bなど）に関係する列名で探す
3. **条件の言葉を、SQLの部品に置き換える:** `sql-handson/04_condition_to_sql.md` の対応表を使う
4. **全部埋めたら、SQL全体を1回通して読む:** 順番や重複に誤りがないか確かめる

## 手本（自作問題）
**条件表**
| 項番 | 列名 | 条件 |
| --- | --- | --- |
| 1 | 受付ID | 8桁の固定長文字。主キー |
| 2 | 顧客ID | 5桁の固定長文字。顧客表の顧客IDを参照 |
| 3 | 区分 | 1桁の固定長文字。空にできない。初期値は'1' |

営業課は、受付IDと区分だけを参照できる。

```sql
CREATE TABLE 受付 (
    受付ID  CHAR(8)  NOT NULL,
    顧客ID  CHAR(5)  NOT NULL,
    区分    [ a ],
    PRIMARY KEY ( [ b ] ),
    [ c ] (顧客ID) REFERENCES 顧客 (顧客ID)
);
GRANT [ d ] (受付ID, 区分) ON 受付 TO 営業課;
```

## 分解
| 空欄 | ① 位置 | ② 本文の行 | ③ 置き換え | 答え |
| --- | --- | --- | --- | --- |
| a | 列「区分」の型と制約 | 項番3 | 1桁の固定長文字 → `CHAR(1)`、初期値 → `DEFAULT '1'`、空にできない → `NOT NULL`。順番は **DEFAULT → NOT NULL** | `CHAR(1) DEFAULT '1' NOT NULL` |
| b | `PRIMARY KEY ( )` のかっこの中（列名） | 項番1「主キー」 | 主キーの列 | `受付ID` |
| c | `(顧客ID) REFERENCES` の直前（制約の種類） | 項番2「〜を参照」 | 他の表を参照する | `FOREIGN KEY` |
| d | `GRANT` の直後（権限の種類） | 「参照できる」 | 参照できる → `SELECT`（列は括弧で指定） | `SELECT` |

## 本文の言葉 → 権限
| 本文の言葉 | 権限 |
| --- | --- |
| 参照できる、見られる | `SELECT` |
| 追加できる | `INSERT` |
| 更新できる | `UPDATE` |
| 削除できる | `DELETE` |

## 共通の型
空欄の前後で何の種類かを決める → 本文の同じ列・同じ表の行を探す → 言葉を部品に直す。この順で解ける。
