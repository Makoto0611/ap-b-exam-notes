# SQL構文表（B科目 問6 用）

過去問で実際に出た型を中心にまとめた。右端の「問題文の手がかり」は、**空欄を見たときに本文のどこを探すか**。自分の手がかりを足していく。

関連: 条件の文→SQLの対応表と例は `01_condition_to_sql.md`、E-R図・正規化・トランザクションは `02_design_basics.md`。

出典メモ: 令4秋 問6（設問3 GRANT／CREATE TABLE、IPA講評で正答率が低い）、令7秋 問6（ALTER・CASCADE・INNER JOIN ON が×）、令和各年の講評で多い型（HAVING、外部結合、IS NULL など）。

## ① 定義（CREATE / ALTER / DROP）
| 構文 | 何をするか | 問題文の手がかり |
| --- | --- | --- |
| `CREATE TABLE 表 (列 型 ..., 制約)` | 表を新しく作る | 「表を作成する」「次の表を定義する」 |
| `列 型 DEFAULT 初期値 NOT NULL` | 初期値あり・空にできない列 | 「初期値は〜」「非NULL」。**DEFAULT → NOT NULL の順** |
| `PRIMARY KEY (列)` | 行を一意に決める列 | 「主キー」。非NULL・重複なしが自動で付く |
| `FOREIGN KEY (列) REFERENCES 表 (列)` | 他の表の値しか入れられない列 | 「〜表を参照する」「外部キー」 |
| `ON DELETE CASCADE` | 親の行を消すと、参照する子の行も連鎖して消える | 「自動的に削除される」「あわせて削除」 |
| `ALTER TABLE 表 ADD 列 型` | **既存の表**に列を足す | 「既存の表を変更する」。CREATEとの違いは「すでにあるか」 |
| `ALTER TABLE 表 DROP COLUMN 列` | 列を削除（依存するものも消すなら CASCADE） | 「列を削除する」 |
| `DROP TABLE 表` | 表ごと消す（DELETEは行だけ） | 「表を削除する」 |
| `CHECK (条件)` | 入る値の範囲を制限 | 「定義域制約」「〜の範囲に限る」 |
| `UNIQUE` | 値の重複を禁止 | 「一意制約」。**主キーには付けない**と書いてあることがある（令4秋 設問2） |

## ② 検索（SELECT）
| 構文 | 何をするか | 問題文の手がかり |
| --- | --- | --- |
| `SELECT 列 FROM 表 WHERE 条件` | 条件に合う行・列を取る | 基本形 |
| `ORDER BY 列 [DESC]` | 並べ替え（既定は昇順、DESCで降順） | 「〜順に表示」 |
| `GROUP BY 列` + `COUNT/SUM/AVG` | グループごとに集計 | 「〜ごとの合計・件数」（令4秋は「部署ごと」「年月ごと」の読み落とし） |
| `HAVING 条件` | **集計後**のグループを絞る（WHEREは集計前） | 「件数が〜以上の」 |
| `A INNER JOIN B ON A.列 = B.列` | 両方にある行だけ結合。**ONは結合条件** | 複合キーは `AND` で全部の列をつなぐ |
| `A LEFT OUTER JOIN B ON ...` | Aの行は全部残す。Bに相手がいなければ B の列が NULL | 「〜がない場合も含めて」「全件」 |
| `列 IS NULL` | 値がない行（`= NULL` は使えない） | 「未入力」「まだ〜ない」 |
| `WHERE 列 > (SELECT ...)` | 副問合せ（内側の結果を条件に） | 「平均より大きい」 |
| `EXISTS (SELECT 1 FROM ... WHERE 外側の列 = ...)` | 条件に合う行が存在するか | 「〜が存在する」 |
| `UNION` | 2つの検索結果を縦に合体（重複は除く） | 「〜と〜をまとめて」 |

## ③ データ操作（INSERT / UPDATE / DELETE）
| 構文 | 何をするか | 注意 |
| --- | --- | --- |
| `INSERT INTO 表 (列,...) VALUES (値,...)` | 行を追加 | 列を省略するとDEFAULTが入る。試験では `:変数` で埋込みの形も出る |
| `UPDATE 表 SET 列 = 式 WHERE 条件` | 行を更新 | **WHEREを忘れると全行更新** |
| `DELETE FROM 表 WHERE 条件` | 行を削除 | WHEREを忘れると全行削除。表ごとなら DROP |

## ④ 制御（GRANT / REVOKE / COMMIT / ROLLBACK）
| 構文 | 何をするか | 問題文の手がかり |
| --- | --- | --- |
| `GRANT 権限 ON 表 TO ユーザ` | 権限を与える | 「〜が参照できる」「アクセス権」 |
| `GRANT SELECT (列, 列) ON 表 TO ユーザ` | **列を絞って**参照権限を与える | 「暗証番号は上長だけが参照」→ 列を指定する（令4秋 設問3 j） |
| `REVOKE 権限 ON 表 FROM ユーザ` | 権限を取り消す（TOではなくFROM） | 「権限を取り消す」 |
| `COMMIT` / `ROLLBACK` | 更新を確定／取り消す | 「処理を確定」「元に戻す」 |

## ⑤ ER図・テーブル設計の読み方（問6設問1）
| 項目 | 覚え方 |
| --- | --- |
| 外部キーを持つ側 | E-R図で「多」の側 |
| 矢印 | 凡例に必ず従う。多の側へ向ける（文字ではなく矢印で答える問いがある） |
| 自己参照 | 同じ表の中で、列が自分の主キーを参照する（部署の上位部署IDなど） |
| 複合主キー | 2列以上で1つの主キー。結合のONも全列を AND でつなぐ |
| 属性の置き場所 | 「年月ごと」「2年ごとに交換」など本文の事情を、属性・関連に1つずつ対応づける（令4秋 1a・b） |

## 混同しやすい組
| 組 | 違い |
| --- | --- |
| CREATE と ALTER | 新しく作る／すでにある表を変える |
| DELETE と DROP | 行を消す／表ごと消す |
| WHERE と HAVING | 集計の前に絞る／集計の後に絞る |
| GRANT と REVOKE | 与える（ON … TO）／取り消す（ON … FROM） |
| COMMIT と ROLLBACK | 確定／取消 |
| INNER JOIN と LEFT OUTER JOIN | 両方にある行だけ／左は全部残す |
| `= NULL` と `IS NULL` | 前者は常に偽。NULLの判定は IS NULL |

## SQLiteと試験の違い（ハンズオンでの注意）
- `GRANT` / `REVOKE` は使えない（書くだけで練習）
- 外部キーは `PRAGMA foreign_keys = ON` で有効にする（`sql.py` は自動で有効）
- `ALTER ... ADD FOREIGN KEY`、`DROP COLUMN ... CASCADE` は使えない（作り直しで代用）
- `ALTER COLUMN` による型変更は使えない
