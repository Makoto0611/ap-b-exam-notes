# プロジェクトマネジメント 07 全体像（プロセス群・知識エリア・スコープ・統合・終結）

過去問の本文は載せない。PMBOK系の用語の整理だけを書く。

## 1. 5つのプロセス群

| プロセス群 | 内容 |
|---|---|
| 立ち上げ | プロジェクト憲章の作成、ステークホルダの特定 |
| 計画 | スコープ、スケジュール、コスト、リスクなどの計画 |
| 実行 | 計画に従って作業し、成果物を作る |
| 監視・コントロール | 進捗・コスト・品質の測定、変更の管理 |
| 終結 | 成果物の引渡し、教訓の記録、資源の解放 |

## 3. スコープ管理

| 用語 | 意味 |
|---|---|
| プロジェクト憲章 | プロジェクトの目的、権限、PMの任命を正式に認めた文書 |
| プロジェクトスコープ記述書 | 成果物、除外事項、前提条件を書いたもの |
| WBS | 作業を階層に分解したもの。最下位は「ワークパッケージ」 |
| WBS辞書 | WBSの各要素の説明（担当、期間、成果物） |
| スコープクリープ | 承認なしに、スコープが広がること |
| スコープの確認 | 成果物を顧客が正式に受け入れること |

- 100%ルール: WBSは、スコープの全てを（過不足なく）含む。

---

## 4. 統合管理・変更の扱い

- 統合変更管理: スコープ・スケジュール・コスト・品質・リスクを横断して、変更の影響を評価し、承認する。
- 変更が必要なときは、影響分析 → 承認 → 計画の更新（ベースラインの更新）の順。

---

## 5. 終結

- 成果物の検収・引渡し
- 契約の終結
- 教訓（レッスンズラーンド）の記録
  - 目的は、次のプロジェクトで、同じ失敗をしないこと
- 資源の解放、文書の保管

---

## 6. 開発プロジェクト特有の観点

- 工程の進め方: ウォーターフォール（工程を順に進める）／アジャイル（短い反復で価値を届け、計画を適応させる）
- アジャイルの進捗の見方: ベロシティ（反復あたりの完了量）、バーンダウンチャート
- 品質: 各工程で、レビューとテストをして、後工程に欠陥を流さない（早く見つけるほど、直すコストが小さい）
- 受入れ: 利用部門が受入れテストをして、検収する

## 7. 用語の対（混同しやすいもの）

| 対 | 違い |
|---|---|
| スコープ確認 と 品質管理 | 前者＝顧客が受け入れる／後者＝品質基準を満たすか確認する |
| 品質保証 と 品質管理 | 前者＝プロセスを守る（予防）／後者＝成果物を測る（検出） |
| 回避 と 軽減 | 前者＝原因をなくす／後者＝確率や影響を下げる |
| クラッシング と ファストトラッキング | 前者＝資源の追加／後者＝作業の並行化 |
| 構成管理 と 変更管理 | 前者＝版を管理する／後者＝変更を承認する |

## 8. 確認問題

- 先に自分で選んでから ▶を開く対象はこのファイルの内容だけ

**問1** 成果物を、顧客が正式に受け入れることはどれか。
ア 品質管理　イ スコープの確認　ウ 品質保証　エ 変更管理

<details><summary>答えと解説</summary>
イ。スコープの確認は、顧客が受け入れる。品質管理は、品質基準を満たすか確認する。混同しやすい対なので、「誰が」「何をするか」で見分ける。
</details>

**問2** 品質保証と品質管理の違いとして適切なものはどれか。
ア 品質保証はプロセスを守る（予防）、品質管理は成果物を測る（検出）　イ 品質保証は成果物を測る、品質管理はプロセスを守る　ウ どちらも同じ意味　エ 品質保証は顧客が行い、品質管理は開発者が行う

<details><summary>答えと解説</summary>
ア。保証は予防（プロセス）、管理は検出（成果物）。
</details>

**問3** リスク対応で、「原因をなくす」のはどれか。
ア 回避　イ 軽減　ウ 受容　エ 転嫁

<details><summary>答えと解説</summary>
ア。回避は原因をなくす。軽減は、確率や影響を下げる。
</details>

**問4** 承認なしに、プロジェクトのスコープが広がることを何というか。
ア スコープクリープ　イ ベースライン　ウ WBS辞書　エ 100%ルール

<details><summary>答えと解説</summary>
ア。スコープクリープ。変更が必要なときは、影響分析→承認→計画の更新（ベースラインの更新）の順。エは、WBSがスコープの全てを過不足なく含む、というルール。
</details>

**問5** 終結で、教訓（レッスンズラーンド）を記録する目的はどれか。
ア 契約を終わらせるため　イ 次のプロジェクトで、同じ失敗をしないため　ウ 資源を解放するため　エ 成果物を引き渡すため

<details><summary>答えと解説</summary>
イ。終結の作業は、成果物の検収・引渡し、契約の終結、教訓の記録、資源の解放、文書の保管。教訓の目的は、同じ失敗をしないこと。
</details>
